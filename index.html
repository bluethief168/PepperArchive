  • 加密：在“加密”标签页里，文本和文件共用一个表单，口令可留空（留空则不加密，只做压缩+校验）。新加密默认用 Argon2id：平衡 64 MiB / t=3 / p=4，强 128 MiB / t=3 / p=4（默认），高强 256 MiB / t=3 / p=4，也可自定义；PBKDF2 只用于恢复旧备份。加密时显示进度条、百分比、预计剩余时间和已流逝时间，完成后在结果区和状态里都显示实际生成时间；取消按钮可随时终止 Argon2id 计算。

安全提醒

密码与加密文件请分开安全保存。遗失密码后无法恢复。参数副本不包含密码或 AES Key，也不能替代加密文件。电子目录也不是密码备份：它只保存索引信息；目录 JSON 本身未加密，请像地址簿一样妥善保存。

关于与威胁模型

PepperArchive 用于保护静态密文在被他人获得后的内容机密性与完整性。核心算法为 AES-256-GCM，密码通过 Argon2id 派生；m/t/p 可自定义并随加密对象保存；旧容器仍可用 PBKDF2-HMAC-SHA-256 解密。

它不能防御已感染恶意软件的设备、键盘记录器、恶意浏览器扩展、屏幕录制、被篡改的本 HTML、弱密码、浏览器漏洞或用户遗失密码。

文件容器会自描述格式版本、KDF、Argon2id/PBKDF2 参数、Salt、Nonce 策略、Chunk Size 等必要恢复参数。原始文件名、MIME、可选 SHA-256 等放在加密 Metadata 中。

纸质恢复格式把 Ciphertext / Parliaments / Key 分别分片，每片含对象类型、集合标识、页号与独立校验。标准 QR 解码能力不可用时，备用图码 提供内置离线视觉识别备用恢复路径；恢复成功后，密码模式必须同时具备正确密码、参数包和密钥包，并通过 AES-GCM 认证。纸面只包含机器恢复所需信息，不打印账户名称或用途。

目录是独立的本机索引，只保存名称、分类、备注、档案编号、状态和时间，不保存密码、密钥秘密或密文。目录可导出为 JSON/CSV；导出文件本身未加密。

Argon2id 实现包含 RFC KAT、多组 Unicode/并行度/多轮参数测试以及 m/t/p 合法性与有效内存对齐校验。

大文件核心按 Chunk 处理，但实际最大可处理大小仍受浏览器内存、临时存储和文件保存 API 限制。iOS 等环境缺少增强文件 API 时，会安全降级为 Blob 下载路径，而不会降级加密强度。
